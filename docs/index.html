Component and token reference

Every component and token in AODS, with the rules that hold the two together. The page is generated from the files the products build from, so the specimens are the live components and the values in the tables are the values that ship.

For designers choosing a component, engineers taking its markup and token names, and anyone checking what was decided. Sections start closed — open one, or use the chips to go straight to a component.

Laws

Every system law, one sentence each, grouped by topic. The label is the gate that checks it: R in build/build.py, P in build/lint_pages.py. A rule about one component lives on that component's record. manifest.laws has them as data.

    Token tiers

    Three tiers, one direction. A component reaches a c- token; the token reaches an s- intent; the intent reaches a g- value. Dark is not a mode: it is a variant, data-surface="dark", allowed only on the components the registry marks dark-capable. Inside one, the s- tier re-points and every dark-capable child follows; inputs never do.

    the chain, for one token

    .aods-button[data-variant="primary"] { background-color: var(--c-button-primary-fill); }
  --c-button-primary-fill : var(--s-color-action-base)      /* tokens/c.json  */
  --s-color-action-base   : var(--g-color-brand-vivid-50)     /* tokens/s.json  */
  --g-color-brand-vivid-50  : #017097                         /* tokens/g.json  */

    Icons

    Forty marks from IBM Carbon (@carbon/icons, Apache 2.0), mapped to our names. One mark costs a <use>: the sprite is injected once per document by aods.js, so a page with sixty icons carries one copy of the paths. Size is a token, color is currentColor.

    The geometry

    Set
    IBM Carbon, @carbon/icons, Apache 2.0. assets/icons/icon-data.js records the upstream Carbon name behind every one of our names, so the mapping is auditable and a swap is a data change, not a redraw.
    Grid
    32 × 32 — IBM Carbon's grid. Its marks sit inside a 2px safe margin, so they read a little quieter than a full-bleed set at the same box size.
    Stroke
    None. Carbon converts its outlines to FILLED paths, so there is no stroke to weight and nothing to tune. A mark paints with fill: currentColor.
    Radius
    Carbon's own. Not ours to set.
    Curves
    Carbon's decision, not ours. Its marks curve where the subject is round and cut where it is not.
    Logos
    No longer a separate case — every Carbon mark, logos included, fills the same way.

    Sizes

    Five rungs, all bound to s.size.icon-*. Pick by what the mark sits next to, not by taste: a mark beside 13.5px text is sm; a mark inside a control is md; a mark standing alone is xl or larger.

    * icon-xs (12px) is a token but not a data-size: it exists for separator furniture set in CSS, like the breadcrumb chevron.

    Tones

    A mark takes the ink of whatever it sits in. data-tone is an override for the cases where it must not — a status mark, a mark on a filled control.

    defaultsecondarytertiarydisabledactionaccenterrorwarningsuccessinfoemergency

    Accessibility

    A mark that repeats the words beside it is decorative and takes aria-hidden="true". Most marks in a real interface are decorative.

    A mark carrying meaning nothing else carries takes role="img" and an aria-label saying what it MEANS, not what it depicts — the external mark is labeled “Opens in a new tab”, never “arrow”.

    An icon-only control labels the control, not the mark; the mark inside stays hidden.

    Never a <title> inside a symbol — every instance on the page would share it.

    Status

    Five marks, five silhouettes. No two statuses may share a shape — that is the ruling, and it is why error sits in a circle while close is a bare X. Color is never the only signal: every status mark sits beside real words.

    error

    Something failed. It has to be fixed.

    STATUS. Circle plus X. The circle is what separates it from close, which is a bare X — that distinction is the whole reason the enclosure exists.

    warning

    Something needs attention but has not failed.

    STATUS. Triangle plus bar. The only status on a triangle.

    info

    Neutral context. Nothing is wrong.

    STATUS. Circle plus i.

    success

    It worked.

    STATUS. Circle plus check.

    emergency

    Stop. The highest interrupt rank.

    STATUS. Hexagon plus bar. The only status on a hexagon, and never used for anything less than rank 1. Carbon has no octagon carrying a mark, and a bare octagon is a blob at 16px — the hexagon keeps a distinct silhouette AND a readable bar, which is what the ruling was for.

    Navigation and direction

    Chevrons move through hierarchy; arrows move through a journey. They are not interchangeable, and doubling a chevron means paging, not nesting.

    chevron-down

    This will expand. Disclosure, accordion, select, footer sitemap.

    Rotates 180° when open — the rotation is the state, not a second mark.

    chevron-up

    This will collapse; or scroll back to the top.

    The mirror of chevron-down for the cases where rotation is not available.

    chevron-right

    Go one level in. Breadcrumb separator, in-page-nav, list rows.

    As a separator it takes the 12px rung: the set draws edge to edge, so a 16px box puts it above the weight of the text it divides.

    chevrons-left

    Previous page.

    Doubled, so it cannot be confused with a single-step chevron used for hierarchy.

    chevrons-right

    Next page.

    Doubled, same reason. Pagination only.

    arrow-left

    Back — to the previous step or the referring page.

    A journey, not a hierarchy. Use a chevron for hierarchy.

    arrow-right

    Forward — continue, next step, read on.

    The trailing mark on a call to action.

    menu

    Open the navigation drawer. The compact header only.

    Three full-bleed rules. Pairs with close, which replaces it while the drawer is open.

    external

    This link leaves the site, or opens a new tab.

    Trailing, at the end of the link text. It carries meaning nothing else carries, so it is labeled 'Opens in a new tab' — never 'arrow'.

    Action

    Things a person does. Each one names an act, and the pairs (download/upload, thumb-up/thumb-down) are never used alone.

    search

    Find within this page or this collection.

    The lens is one of the two places a curve is allowed — the subject IS a circle. Pairs with the search component; never use it as a generic 'magnify' or 'zoom'.

    close

    Dismiss this thing. Modal, toast, drawer, removable chip.

    A BARE X — it never sits inside an enclosure, so it can never be misread as error. Not the same act as clear.

    clear

    Empty this field.

    A backspace hexagon, not an X. Clearing what you typed and dismissing a thing are different acts and get different marks.

    check

    Done, selected, included.

    A bare check with no enclosure — the mark inside a checkbox or a selected option. For a status message use success.

    copy

    Put this on the clipboard.

    Two offset rectangles. Pairs with a toast confirming the copy actually happened.

    download

    Take a copy of this file.

    Arrow into a tray. The direction is the whole meaning; do not mirror it for upload.

    upload

    Send a file from your machine.

    Arrow out of a tray. The mirror of download, and they must never be swapped.

    print

    Print this page or this record.

    The physical device, because print is still a physical act to the person doing it.

    send

    Submit this message.

    The conversational composer. Not a generic submit — a form's submit is a button with a word on it.

    retry

    Try that again.

    A broken loop with an arrowhead. Failure recovery — pair it with an error alert, never with a plain refresh.

    thumb-up

    This answer helped.

    Conversational feedback. Always paired with thumb-down; a single thumb is a trap.

    thumb-down

    This answer did not help.

    The pair. Offering only one direction makes the control useless as a signal.

    Object and attribute

    What a thing IS, rather than what you do to it.

    file

    A document, of unstated type.

    Generic. If the type matters, say the type in words — the set does not carry per-format marks.

    calendar

    A date, a deadline, a schedule.

    Never a date PICKER trigger on its own — a date field is a field with a label.

    lock

    Secure, or restricted.

    The shackle is round because the object IS round — squaring it turns the lock into a suitcase. One of the four sanctioned curves.

    help

    Explain this.

    Circle plus question mark. Reads as an offer, not a status — pair it with a disclosure or a tooltip, never with an alert.

    quote

    A pulled quotation.

    Two marks, not one. The pull-quote component; never decoration inside running prose.

    filter

    Narrow this set.

    A funnel. Distinct from sort, which reorders rather than removes.

    sort

    This column can be sorted. Nothing is applied yet.

    The neutral state of a sortable table head. Must be replaced by sort-asc or sort-desc once a direction is chosen.

    sort-asc

    Sorted A→Z, low→high, old→new.

    Table heads. aria-sort='ascending' on the th is what a screen reader hears; the mark is decorative.

    sort-desc

    Sorted Z→A, high→low, new→old.

    The mirror. Same aria rule.

    Brand

    Supplied artwork. Filled, unstroked, and exempt from every geometry rule above. Do not redraw them in the house hand — a brand mark that is not the brand's mark is worse than no mark.

    social-facebook

    Facebook.

    BRAND. Supplied artwork, filled and unstroked, exempt from every geometry rule. Do not restyle into the house hand.

    social-instagram

    Instagram.

    BRAND. Same rule.

    social-linkedin

    LinkedIn.

    BRAND. Same rule.

    social-x

    X.

    BRAND. Same rule.

    social-youtube

    YouTube.

    BRAND. Same rule.

    Component index

    Every component, one row each, grouped by family: named for the end the user has in mind, not for how the component is built. The families follow this index in the order manifest.families gives them, each opening with what the user does with it. Every entry shows the same markup twice — on a light ground and on a dark one — then its props, its states, its HTML, and the component-tier tokens it binds. If a value is not in that table, the component does not get to have it.

    Open questions

    Decisions I made to keep building. Each is reversible in one token.

    1. Secondary outline on dark. A vivid/50 outline on primary/80 is ~2.3:1. I stepped it to vivid/30 on dark (s.color.action.outline). The primary fill stays at 50 per the rule.
    2. Dark borders. "One step down" read as the mirror of light: page primary/80 → border primary/70; raised 70 → 60; sunken 90 → 80. If "down" meant darker, flip three $dark values in s.color.border.*.
    3. Radio shape. Radius is 0 everywhere, so the radio is a square with a square dot. If the radio earns an exception, add "$allow-radius": true on a new s.radius.radio and the lint will let it through.
    4. Status border step. Alert and badge borders use status/20, not /10 — the 5→10 pair is near-identical across nine families (reference/core-color-swatches/NOTES.md, one level above the system), so /10 on a /5 surface vanishes.
    5. Which children flip. text, badge, divider, button-group and label flip inside a dark surface. Checkbox, switch and field flip partially — label and help text only, declared as darkTokens in the registry — so the control itself stays light per the ruling. Input, table, form, footer never flip.
    6. Text on dark. Dark ground text is brand-gray 10 / 20 / 30. No dark-specific white was asked for.
    7. Emphasis on non-cards. Alert uses a 3px leading edge in its status color and the modal uses emphasis-3 in vivid/40, both by the same outside-shadow device. Say the word and they drop to plain borders.
    8. Disclosure, from the v0.4.0 spec. Four values were off the ramp and snapped to the nearest rung: bar inset 28→32px, bar gap 18→20px, open rule 4→3px (the 3px emphasis rung), row inset 10→8px. The bullet kept 6px via a new s.size.bullet. The spec's three grounds map to two: page is rest, inverse is data-surface="dark" on the block, and inverse-bar is the same attribute on the summary part alone — so the placeholder name is gone. On dark, closed = dark sunken (primary/90) and open = dark raised (primary/70), following the surface ruling rather than the spec's #072543 closed bar; say if the bar should sit lighter than its page.
    9. Stat, from the v0.3.0 spec. Start inset 28→24px; everything else on the ramp (4 / 48 / 10 / 8). The label's primary/50 → primary/20 pair is a new s.color.text.brand-tertiary; the rule's vivid/50 → vivid/40 sibling pair is s.color.border.vivid, kept as a pair per the spec's warning. The valence question (a harmful number arrives in the same gold) is still yours.
    10. Feature rule color and border weight. The card-feature spec draws the rule and a 2px top/right/bottom border in vivid/50. I kept the emphasis ruling — 1px hairline and rule both in vivid/40 — and changed only the shape. If the feature level should step up to vivid/50 and 2px, that is two tokens.
    11. Conversational radius. R6 now accepts a radius whose reference chain carries $allow-radius; only s.radius.conv-* (4 / 8 / 16 / pill) does. Nothing outside aods-conv-* can reach them without the lint naming it.
    12. Conversational on dark. Built light-only — it was not in the dark-capable list. If an AI panel ever sits on a dark hero, say so and the family gets ground: dark like the rest.
    13. Footer, from AODS.footer.desktop. Layout kept band for band; every value is V4's. Two things did not survive: the round social buttons (radius ruling — 40px squares on the raised surface) and Inter. The reference is dark, so the dark variant is shown first; the light footer is the same markup without the attribute. Content stops at a new s.size.measure-page (1440px).
    14. Header, from AODS.header.desktop. Utility bar always dark (it carries data-surface="dark" as a part); internal bar 56px opaque, landing bar 80px at 80% via a new s.color.surface.glass — the only translucent surface in the system, white at 80% on light and primary/80 at 80% on dark. The reference was 60%; raised a third by ruling. Over a busy hero the bar text may drop under 4.5:1, which is the page's responsibility. The mega menu is the sunken surface with hairlines; the nav indicator is the action outline color. Reference chevrons were bitmaps; these are drawn.
    15. Form group gap. You said "maybe 24"; I set 32 — double the in-group 16 — so the two rhythms cannot be confused at a glance. One token (c.form.group-gap) if 24 reads better.
    16. Step indicator. Circles kept by ruling — s.radius.step is the second $allow-radius token. The reference's 4px ring → 3px rung; 8px connector → 6px rung. The reference's teal became brand-vivid; the current step uses the selected surface (vivid/10) with a vivid ring. Light-only.
    17. Typography patterns. eyebrow, section-heading, pull-quote and summary-box are in from the 06 sheet; band-opener merged into section-heading by your ruling (data-scale=display). aods.office-card is not built — it needs a decision on how program offices enter V4 (there is no office axis in the tokens). summary-box has one polarity per R-KIND. Page templates (2026-08-23): ten whole pages made only of system components — shell, landing, program, article, press release, data, form, search, emergency, assistant — at templates/index.html, each with a self-contained .bundle.html; their component order is manifest.pages.
    18. section-opener (was aods.goal-header). Renamed for the role, not the content: it opens a numbered section that has a picture; section-heading at display scale is the same ramp without the media column. Spec snaps: stack 18→20, eyebrow gap 14→12. The 520×340 media is two new rungs (s.size.media-width/height) so the image never distorts; the column caps at 45% and stacks under the copy below 900px.
    19. objective, from aods.objective. Corrected 2026-08-22: it is a text layout block, not an expander — index and title on a bar, the argument beside a strategies column, always open, no states; now in the blocks family. Kept the spec's name because it names a payload, not a look. Three snaps: index gutter 60→56px (new s.size.index-column), strategies column 500→480px (new s.size.measure-aside), bar bottom inset and gap 18→20px. The 6px strategy bullet is a circle — the spec draws a dot, and a bullet is a glyph, not a corner; say the word and it squares like the disclosure bullet. The top rule uses the divider pair (gray/30, dark primary/50) for the spec's #D4CECA / #CEDEEE.
    20. reference-list. Click only, by your ruling — the hover preview is gone. All rows start closed; the open item carries no rule at all and its citation steps to text-primary. It has a surface: page-toned, 64px inset (spec 72 → 64 rung), and the open item is a raised note. Dark variant from the dark mock: its trim flips (darkTokens); the list sits on the dark page (primary/80) so it blends into the footer — the mock's #1E374F is primary/60, off the surface ramp — and the note is a new s.color.surface.note: raised on light, vivid/10 on dark for the mock's #E7F8FD. The triangle is a new s.color.accent.soft (accent/30). Snaps: row gap 10→8, inner gap 14→12, quote rule 4→3.
    21. Motion. By your ruling every state change eases: one duration (c.page.motion-state, 160ms) bound once in the scoped reset for color, fill, border, shadow, ring, opacity and transform. The hover wash became a registered @property color painted as a gradient, because a plain gradient cannot transition. Open/close on every <details> component grows and shrinks the panel in aods.js; without the script it still opens, just without the ease. prefers-reduced-motion turns all of it off.
    22. Vocabulary migration (audit #2). Done 2026-08-21: 128 per-block re-exports collapsed onto c.page.* (focus, hover/pressed wash, hairline, motion, radius) and 211 tokens renamed to one vocabulary — *-ink, logical insets, state last, rule inside blocks. R10/R11 keep it that way. The rule — a black wash on a light fill, a white wash on a dark one, decided by the FILL not the ground — is kept by a generated pin: every component that stays light inside a dark surface (inputs, checkbox, switch, chip, steps, table, the conversational family) re-pins the wash and the focus ring to their light values. Your question caught that the first cut of the collapse had lost the flip entirely. Map: audit/RENAME-MAP.json.
    23. Compact header and footer (AODS.header.mobile / footer.mobile). Layout only from the mocks, every value V4's. Both use a container query on the component (≤ 900px of its own width), so the docs can show a 375px specimen beside the wide one and a narrow pane gets the same result as a phone. Snaps: bar 60 → 48 + 2×8; logo 32 → 24; sub-link gap 10 → 8; site-map bar 64 → 48 + 2×8. The spec's 3px drawer frame in utility navy became the sunken step on each ground; its Inter became Outfit. The mega panels move inline by script (aods.js) — without it the drawer still opens and the panels still show under the bar, just not indented under their item.
    24. Rulings 2026-08-22. Hit targets: 44px in the compact layout, 24px wide. Focus ring outside everywhere with a small gap. Indicator: horizontal sets mark the selected item along the bottom, vertical sets along the leading edge; tabs gained data-numerals (code-face numeral in accent/70) from the V3 segmented tab. Reference-list dark ground is a sixth surface step, s.color.surface.elevated (primary/60), and its open note is vivid/10 with accent/80 text. The block was rebuilt for this interaction: no gap between items, each a rule-to-rule slot (12px inset, 44px rows), every row and note bleeding 8px past the index — so hover, pressed and the open card are the same shape by construction rather than by negative margins. After a press the hover wash fades away until the pointer leaves and returns.
    25. Rulings 2026-08-22, second round. Status colors step to 30 on dark. Form group gap is 24. The single-consumer s- tokens stay until every component exists (orphan optimization comes last). Token suffixes stay and must be prop values (my call: a parseable name beats a second lookup). The modal edge is the card's emphasis device only. Eight inventory components were built from the system's own rules ahead of their mocks — skip-link, gov-banner, breadcrumb, in-page-nav, pagination, search, toast, error-summary — correct them from here. Fluid type: two comparison pages in ../audit/fluid-type/, awaiting the call.
    26. Outfit weights. Only 400 and 500 were supplied. ui roles never ask for more; heading is Lato 700. Newsreader has 400, 400i, 600 — body semibold resolves to 600.
